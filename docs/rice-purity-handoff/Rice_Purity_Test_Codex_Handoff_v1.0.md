## 1. 产品范围与非目标

### 首版必须完成

| 模块 | 必须可用的能力 |
|---|---|
| 首页 | 介绍、评分规则、内容提示、开始／继续测试、FAQ、关于与隐私入口。 |
| 答题 | 一次一道题，有／没有，上一题，暂时跳过，进度，返回修改，刷新恢复或明确降级提示。 |
| 收尾检查 | 有遗漏时提示；可回补，也可结束并查看明确标识的未完成摘要。 |
| 结果 | 实际计算的分数或未完成状态、简明解释、答题摘要、默认折叠的回答明细、修改答案、重新测试。 |
| 双语 | 中文、英文、双语对照；切换不重置答题；界面、题目、提示和 PDF 文案完整覆盖。 |
| PDF | 浏览器内生成真实 PDF；正式完整结果默认一页 A4 摘要；加载、失败、重试、打开／保存入口。 |
| 质量 | 桌面和手机布局、键盘可操作、基本无障碍、错误处理、计分单测、核心流程测试。 |
| 部署 | 可构建静态文件；给出与实际托管平台匹配的路由回退和资源路径说明。 |

### 首版不做

账号和云同步、数据库、长期历史记录、分享结果链接、社交发布、排行榜、群体平均分、人格标签、心理雷达图、AI 解读、支付、后台题库 CMS、PWA／离线缓存框架、复杂动效系统、默认完整逐题 PDF。

这是一份经历问卷，不是医学或心理诊断，不输出品德、人格或个人价值判断。不使用“优秀／危险／堕落／完美纯洁”等等级，不鼓励把题目当成待完成清单。

## 2. 技术架构

### 2.1 推荐组成

| 层 | 选择 | 约束 |
|---|---|---|
| 应用 | React + Vite + TypeScript | 保留已有兼容版本；新项目选择相互兼容的稳定版本并提交锁文件。 |
| 路由 | React Router，轻量客户端模式 | 不为这个项目引入 SSR 或完整服务端框架。 |
| 图标 | `lucide-react` | 按名称导入实际使用图标，不动态装入整个图标库。 |
| 状态 | `useReducer` + Context | 业务状态集中；不要给每个页面各存一份答案或分数。 |
| 样式 | CSS Modules + CSS 变量 | 若已有成熟 Tailwind 配置可复用；不要为换技术栈重做已有样式。 |
| 题库 | 本地 TypeScript／JSON | 固定题目 ID、双语文本、版本及审核状态。 |
| 临时保存 | React 内存 + `sessionStorage` | 答案不进入 `localStorage`、URL 或网络载荷。 |
| PDF | `@react-pdf/renderer` | 动态加载、独立排版，不把网页截图塞进 PDF。 |
| 测试 | 优先复用现有测试；无则 Vitest + Testing Library + Playwright | 先覆盖业务正确性和核心流程，不搭建庞大的测试平台。 |

Vite 默认构建产物为 `dist`，可以部署为静态站；`vite preview` 用于本地预览，不是生产服务器。[S1] React Router 官方提供基于 Vite 的声明式接入方式。[S2] Lucide 的 React 图标是独立 SVG 组件，支持按需打包。[S3]

React reducer 必须保持纯函数；不要在 reducer 中写存储、生成文件、请求网络或读取当前时间。需要时间戳时由事件处理层传入。不要在 `dispatch` 后立刻读取旧 state 计算最终结果。[S4]

### 2.2 版本与依赖边界

不要在文档中猜测或在代码中混搭“最新版本”。实现时核实 React、Vite、Node、React Router、PDF 库之间的兼容性，以锁文件和实际构建为准；在 README 记录实际版本及运行要求。[S5]

生成 PDF 使用 `@react-pdf/renderer`，不要误装成仅用于展示现有 PDF 的其他同名库。不要为首版再引入另一套 PDF 引擎，除非实际验证后发现不可解决的兼容问题，并说明原因。

所有回答、计分和报告处理在浏览器执行。静态资源托管仍然存在；“纯前端”不等于完全没有网络请求，也不自动意味着首次加载后所有内容都可离线使用。

## 4. 页面与路由

| 路径／状态 | 内容 | 进入条件 |
|---|---|---|
| `/` | 首页、FAQ、关于说明 | 无。 |
| `/test` · answering | 当前一道问题 | 已初始化有效测试会话；无会话时引导开始。 |
| `/test` · review | 收尾检查和遗漏回补入口 | 到达最后一题后存在遗漏。 |
| `/test` · editing | 从结果或检查页进入单题修改 | 必须有有效会话；保留返回目标。 |
| `/result` | 完成结果或未完成摘要 | 当前会话经过完成／结束动作，且状态校验通过。 |
| `/privacy` | 简短真实的隐私与清除说明 | 无。 |
| `*` | 友好未找到页面 | 提供回首页入口。 |

不生成 100 个页面文件，也不向浏览器历史写入 100 次逐题路由。题目切换是 `/test` 内的状态变化。“上一题”负责逐题回退；浏览器后退保持正常页面导航，不得因此清空答案或重复提交。

FAQ 和 About 首版使用首页真实锚点，不必新建两套内容页。移动端收敛导航，保持品牌、语言和必要操作即可。

禁止用 `?score=72`、URL hash、路径参数、Base64 或分享链接保存答案／分数。直接访问 `/result` 且没有有效会话时，显示“暂无本次测试结果”并引导开始，不能展示默认 72 分或伪造报告。

开发视觉预览只允许 `import.meta.env.DEV` 下的入口或本地组件样例；生产构建不得可访问假结果预览。使用明确的“设计样例／非真实测试结果”标识。

## 5. 首页规格

品牌名称：英文 `Rice Purity Test`，中文显示 `纯洁度测试`。没有真实授权依据，不加 `Official`、大学标识或“官方认证”。

首屏包含简短标题、双语介绍、`Start test / 开始测试` 和评分说明入口。有当前会话时，主按钮改为 `Continue test / 继续测试`；已结束会话可显示 `View result / 查看结果`。重新开始必须明确会清除本次记录。

正文推荐：

> A questionnaire about life experiences. Your score is not a judgment of your worth.  
> 一份关于人生经历的问卷。分数不代表你的价值，也不评价好坏。

正式 100 题版本可显示“100 questions / 100 道题目”。演示题库只能显示真实题数及“演示版”，不能伪装成完整测试。不写未经计时验证的“2 分钟完成”等承诺。

内容提示应根据实际题库写明是否包含成人、亲密关系、酒精或其他敏感主题；允许退出、跳过，不收集姓名、生日和联系方式。题库的目标年龄和公开发布范围是内容审核项，不能靠一个弹窗就宣布问题全部解决。

FAQ 至少回答：如何计分；分数是否有好坏；跳过如何处理；答案是否上传；如何保存 PDF。避免首页与结果页重复展示整套营销模块。

## 6. 单题答题页规格

### 6.1 页面构成

顶部保留品牌、语言切换和返回首页入口。中间使用宽约 680–760px 的单题区域，依次显示进度、题目、两个答案和次级导航；手机单列。

```text
Rice Purity Test                              语言

Question 12 of 100 / 第 12 题，共 100 题
Answered 10 of 100 / 已回答 10 / 100      [进度条 10%]

Have you ever … ?
你是否曾经……？

[ Yes / 有 ]                [ No / 没有 ]

Previous / 上一题          Skip for now / 暂时跳过

Selecting an answer moves to the next question.
选择答案后进入下一题，可返回修改。
```

题目用真实文本节点，不放进图片。长英文、较长中文和双语题目允许正常换行，不能为了保持固定高度截断。

### 6.2 答题交互

正常答题模式下，点击 Yes 或 No 后保存当前题并进入下一题；不要求每道新题再点一次 Next。选择前明确提示这个行为。

使用轻微的选中反馈和约 200–300ms 的切换保护。保护必须在事件处理入口同步生效，并绑定当前题 ID；防止双击、连续触屏和键盘重复触发误答下一题。不要只依赖视觉动画或异步 state 作为锁。

返回已回答题时显示原选择。再次选择会覆盖该题旧答案，而不是累计扣分；也提供次级“下一题”以便只查看不修改地继续。首题禁用“上一题”。

“暂时跳过”只代表尚未回答。已回答题上不得把“下一题”实现成清除答案；如允许移除原答案，标签必须明确为“清除答案并暂时跳过”。

正常模式最后一题回答后：全部已答则直接进入结果；存在跳过或未访问题则进入收尾检查。最后一题不能因为 React 状态更新时序而漏计。

### 6.3 进度定义

当前题号 = 当前题在固定题库顺序中的位置 + 1。  
已答数量 = Yes 数量 + No 数量。  
进度条 = 已答数量 / 题库总题数。

跳过和未访问都不算已答；不能走到第 100 题就显示 100% 完成，也不能通过切换语言重置进度。

### 6.4 收尾检查与编辑

收尾检查显示还剩多少项，分别识别“暂时跳过”和“未访问”。用户可以逐项补答，也可以选择“结束并查看未完成摘要”。不强迫回答敏感题，但不能把未回答默认变成 No。

从结果页修改答案时，复用单题组件，但进入编辑模式：先修改局部草稿，提供“保存并返回结果”和“取消”，不要保存后自动跳到下一题。取消不改变原答案。来自收尾检查则保存后返回检查状态。

修改生效后重新派生统计和分数，旧 PDF 缓存失效。若清除了一个已答项，完整结果必须变成未完成摘要，不能继续保留原来的正式分数。

退出到首页默认保留当前会话并显示继续入口。只有明确的“清除本次记录／重新测试”动作才清除；该动作需二次确认。

## 7. 题库、状态与计分契约

### 7.1 题库必须可追溯

先查找项目内的题库和翻译，确认实际版本。不得从两张 UI 图拼凑 100 题，不得自动改写／删题后仍宣称与原版完全一致。

若没有正式题库，使用少量非露骨演示题推进界面和流程，明确标注演示。不要生成 97 条重复或虚构内容填满列表。正式发布前必须接入完整、审核过的 100 题；Codex 不能为了通过构建自行把 `draft` 改为 `approved`。

题库文本、来源记录和译稿审核是内容交付，不是本交接包已经提供的材料。技术演示完成不等于正式网站可上线。

### 7.2 推荐数据契约

以下是实现契约示意，可按现有代码调整文件组织，不得改变语义。

```ts
type Locale = 'zh-CN' | 'en';
type DisplayLanguage = Locale | 'bilingual';
type AnswerValue = 'yes' | 'no' | 'skipped';
// answers[id] 不存在 = 从未回答／未访问，不等于 no。
type Answers = Partial<Record<string, AnswerValue>>;

interface Question {
  id: string;                 // 稳定 ID，例如 q001，不用中文句子作键
  order: number;
  text: Record<Locale, string>;
}

interface QuestionBank {
  id: string;
  version: string;
  scoringVersion: 'count-100-equal-v1';
  reviewStatus: 'draft' | 'approved';
  sourceNote: string;         // 实际来源、版本和审核记录，不编造授权
  questions: readonly Question[];
}

interface QuizSession {
  schemaVersion: 1;
  bankId: string;
  bankVersion: string;
  scoringVersion: string;
  answers: Answers;
  currentQuestionId: string;
  phase: 'answering' | 'review' | 'result';
  answersRevision: number;    // 有效答案修改后递增，用于使旧导出失效
  startedAt: string;          // ISO 时间，由事件层生成
  finishedAt: string | null; // 结束／提交时间，不是每次 render 的时间
}

interface Counts {
  total: number;
  yes: number;
  no: number;
  skipped: number;
  unvisited: number;
  answered: number;
}

type Result =
  | { status: 'complete'; score: number; counts: Counts }
  | { status: 'incomplete' | 'demo'; score: null; counts: Counts };
```

界面语言、展开状态、编辑草稿、过渡锁和 PDF 加载状态与答案分开。不要持久化第二份“权威分数”，也不要把完整 PDF Blob 放进 sessionStorage。

### 7.3 计分规则

仅对**已审核、正好 100 题、全部题目均回答 Yes 或 No**的正式题库生成完整分数：

```text
score = 100 - yesCount
answeredCount = yesCount + noCount
isComplete = answeredCount === 100
```

未完成正式问卷：`score = null`，显示未完成摘要。不按已答题数归一化成 100 分，不把跳过当 No，不显示一个暂定的“标准结果”。

演示题库：`status = demo`，显示演示说明和真实答题数量，不宣称获得正式 Rice Purity 分数。72 分视觉预览使用独立的开发样例，不参与真实计算。

统计只遍历当前有效题库的 ID。题库重复 ID、缺少中文／英文、顺序重复等错误必须被验证拦截。恢复的会话若含未知题 ID、非法值或不匹配版本，应拒绝恢复并提示，不能静默迁移成另一份问卷。

实现 `validateQuestionBank`、`validateSession`、`deriveCounts`、`deriveResult` 等小型纯函数。网页和 PDF 都消费同一个派生结果。**0 分是有效结果，不能用 `if (score)` 判断是否有结果。**

题库中改变题意、数量或顺序时更新版本；不得让旧答案自动套用到新题目。首版不做题库版本的复杂自动迁移。

### 8.2 主卡文案

### 8.3 回答明细

默认收起，不预览前三题的敏感回答。`View answers` 展开同一个明细区域、滚动到标题并正确转移焦点，不再创建重复侧栏或第二套列表。

展开后按题库原顺序展示题号、对应语言题文、答案状态及“修改”。状态为 Yes／No／Skipped／Not answered，均为中性样式。100 条普通列表即可，不做虚拟滚动、复杂筛选或额外管理页面。

在结果页展开答案不会使 PDF 自动包含明细。打印结果时也必须继续排除逐题回答。

### 8.4 未完成、无数据和重新测试

未完成摘要显示“测试尚未完成”，主数字为“已回答 X / 100”，不是“X 分”。显示 Yes、No、跳过和未访问数量；主动作是“继续回答”，另可导出明确标识的“未完成答题摘要”，PDF 中不出现正式分数。

无有效会话时显示空状态；损坏数据时提示无法恢复。不从 localStorage、网址或默认 fixture 补出一个结果。

重新测试／清除记录使用简洁确认对话框，明确本次浏览器记录会被清除；默认焦点放在取消。确认后清理应用自己的记录、内存状态、导出缓存和 Blob URL，不删除同域其他业务的存储。已保存到设备的 PDF 不会随浏览器清除动作删除。

## 9. 中英文与双语呈现

首版默认 `bilingual`，与参考图保持中英同屏；菜单提供 `中文`、`English`、`双语` 三种模式。双语默认英文为主行、中文为次行；两个单语模式只展示对应语言。

语言偏好可以单独保存在一个非敏感偏好键中；答案仍只进入临时会话。偏好存储失败也不影响答题。不同语言不能拥有不同的答案数组或不同题号。

所有文案走统一字典，至少覆盖：导航、首页、题目、进度、选项、确认框、空状态、错误、结果、PDF、隐私、无障碍标签。数字和变量用模板插值，不在 JSX 里拼接残缺中英文句子；英文单复数和长文本需测试。

页面 `lang` 与主语言一致，双语块为另一种语言设置对应 `lang`。Lucide 装饰图标设为对辅助技术隐藏；仅图标按钮必须有翻译后的可访问名称。

切换语言不改变题库 ID、顺序、答案、进度和分数。结果和 PDF 跟随选择的语言模式。生成中的旧语言 PDF 不得在语言切换后作为当前报告误下载。

## 10. PDF 规格与导出流程

### 10.1 输出范围

使用 `@react-pdf/renderer` 的浏览器生成能力。官方提供下载组件、Blob 访问和按需生成接口；本项目需要点击后才加载和生成，而不是每次答题重算整份 PDF。[S7]

PDF 是单独设计的报告，不是网页截图。网页组件不能直接当成 PDF 组件使用。首版正式完整结果以一页 A4 纵向摘要为目标，页面边距建议 36–44pt，正文约 10–11pt；中英文对照也应可读，不靠过小字体凑一页。

| 包含 | 不包含 |
|---|---|
| 网站名称、报告标题、分数、答题统计 | 逐题答案、敏感经历详情 |
| 简短解释、计分规则、免责声明 | 人格推断、排名、平均分、虚构认证 |
| 实际题库版本、报告生成时间和显示时区 | 姓名、邮箱、设备标识、跟踪 ID |
| 当前语言或双语内容 | 导航、按钮、FAQ、Hero 人物、社交入口 |

未完成摘要只输出真实计数和“未完成，未生成正式分数”；演示数据输出时必须带“演示／非正式测试结果”标识，不能伪装正式报告。

文件名采用 `rice-purity-result-YYYYMMDD-HHmm-zh-CN.pdf` 等形式，双语后缀 `bilingual`。文件名不写分数或答案。时间取浏览器实际生成时刻并注明显示时区，不硬编码地区，也不宣称是可信签名时间。

### 10.2 中文字体是必测项

PDF 需要单独注册具备中文字符覆盖的字体；网页字体配置不会自动成为 PDF 的嵌入字体。React-pdf 当前文档列出 TTF／WOFF 支持，并提示变量字体限制，实施时按实际安装版本验证。[S8]

从可合法使用的来源取得兼容字体，记录来源和许可，按需使用静态字重。不能默认某个网页 WOFF2 或任意系统字体可用于 PDF。交接包不含字体文件；Codex 不得凭空引用并不存在的字体路径。

生产字体资源应由本站托管并随导出按需加载，不调用把文本送到外部服务的字体／PDF API。字体加载失败时明确提示并提供重试／打印备选，不能生成中文黑方块后报告成功。

### 10.3 导出状态机

```text
idle → loading module/fonts → generating → ready → 发起浏览器保存／打开
                                 ↓
                               error → retry
```

点击导出时，从当前有效会话派生结果并建立只含报告必要数据的不可变快照。绑定题库版本、`answersRevision`、语言、生成时间，防止异步过程中答案变化后下载过期结果。

导出期间按钮显示“正在生成 PDF”，防止重复生成。不用假进度百分比，不用假 loading 延时。页面离开、答案变更、语言切换或记录清除后，旧任务即使完成也不能继续触发下载。

生成成功后提供真实 PDF Blob 的下载／打开入口。部分移动浏览器可能打开预览，由用户保存；以实际浏览器验证为准，不承诺都能自动保存到下载目录。浏览器无法证明用户已将文件写入设备，不显示未经证实的“已保存到你的电脑”。

对象 URL 在更换报告、清除记录或不再需要时释放，不能在浏览器尚未取得文件前立即释放。PDF 出错不能影响继续答题和查看结果。

### 10.4 打印备选

提供小型“打印／保存为 PDF”备选入口；明确它打开系统打印对话框，不是主 PDF 生成功能。[S9]

使用独立的摘要打印布局，`@media print` 隐藏导航、交互按钮、装饰和逐题明细；即使答案区域已展开，也不能打印敏感列表。主 PDF 功能失败不能直接用打印窗口冒充已修复。

## 11. 临时保存与隐私

### 11.1 保存策略

采用一个有命名空间和 schema 版本的键，例如 `rpt:session:v1`。只保存必要会话状态，先验证恢复数据，再开启写入；避免首次挂载用空状态覆盖已有进度。

`sessionStorage` 以来源和标签页分隔，通常可跨刷新保留；恢复会话、新窗口的 opener 等情况有浏览器语义，不能将其描述为安全保险箱或保证关页后不可恢复。[S10]

存储访问、序列化、解析和写入均需 `try/catch`。不可用时回退 React 内存，提示“当前浏览器无法临时保存进度，刷新可能丢失本次回答”；答题和 PDF 仍可使用。不要自动改用长期存储来掩盖失败。

清除只删除本应用自己的键，不能调用 `sessionStorage.clear()` 或 `localStorage.clear()` 清空同域其他应用数据。清除后防止残留的 effect、计时器或导出回调重新写入旧答案。

### 11.2 不得发生的数据流

答案、分数和报告内容不得进入：URL／hash、网络请求载荷、分析事件、错误追踪、控制台日志、广告服务、会话回放、外部 PDF 服务、Cookie 或长期本地答案存储。

不接入第三方统计、客服和录屏脚本。不要调用系统分享或剪贴板接口自动复制回答。生产资源请求可以存在，但与回答处理分开；验收需检查实际网络，而不是仅凭代码中没有 `fetch` 就宣称没有上传。

### 11.3 对外文案

建议短文案：

> Answers are processed in your browser and are not sent to a server by this app. Progress is temporarily kept in this tab and can be cleared at any time.  
> 答案在浏览器中处理，本应用不将答案发送到服务器。进度临时保存在当前标签页，你可以随时清除。

详细说明需补充：共享设备风险；已下载 PDF 不受网页清除控制；托管方可能处理正常访问请求的信息，实际日志配置上线前核查。不要写“绝对匿名”“永不保存任何数据”或“服务器不接收任何信息”。

本地状态可被用户自行修改，因此分数和 PDF 不能被设计成防篡改证明、身份凭据或第三方验证证书。首版不为娱乐问卷构建反作弊系统。

## 13. 可访问性、响应式与性能

键盘可完成开始、答题、返回、修改、导出、收起明细与清除记录；保留明显焦点。按钮使用原生 button，语言选单和确认框采用正确语义，支持 Escape 和焦点返回。

自动进入下一题前说明行为；切换后让新题标题得到适当焦点与朗读，不将焦点留在上一题消失的按钮上。可用单一温和的 live region 播报题号，避免进度、问题、答案多处重复播报。

不依赖悬停才能操作；不使用仅图标而无标签的 Yes／No；触控、键盘重复输入都需测试。尊重 `prefers-reduced-motion`，关闭装饰动画，业务切换保护仍生效。

至少检查 360px、390px、768px、1024px、1440px 宽度，以及 200% 文字／页面放大。双语按钮可以换为纵向布局，不得通过把字体缩小到难以阅读来塞入。

PDF 库和字体不进入答题首屏的同步关键加载路径。尽量不新增动画库；Lucide 按需导入。Hero 素材有则适当压缩、声明尺寸，缺素材用简洁背景。不得在答题时加载跟业务无关的视频或第三方内容。

## 14. 静态部署与错误处理

构建产物部署到实际静态托管平台，不需要长期运行 Node 服务。使用客户端 History 路由时，托管平台需把应用路由正确回退到 `index.html`；真实 JS、CSS、字体和图片不能被错误回退成 HTML。子路径部署要正确配置 Vite `base` 和路由基路径。[S1]

部署位置未知时，先给出需要配置的项目；不要替用户发布到任意账号。只有平台确实不支持所需回退且用户接受地址形式时，才考虑 HashRouter 替代，不能默默改变约定。

`/result` 和 `/test` 不应被当成可公开分享的个人结果资源。可设置结果页不索引，但这不构成访问控制或隐私保障。首版不承诺靠 SPA 自动实现完善的双语 SEO；SEO 扩展另行确定。

需要覆盖：无会话、无效／损坏会话、题库版本变化、存储失败、字体加载失败、PDF 生成失败、资源加载失败和未知路由。所有错误提示双语齐全，恢复动作明确；没有结果时不展示伪造分数。

## 16. 实施顺序与完成报告

### 阶段 A：检查与基础契约

核实仓库、参考图、题库、字体／插画素材、依赖与部署情况；列出实际发现。建立数据类型、题库验证、计分函数和关键单测。缺题库不阻塞框架，但保留内容阻塞项。

### 阶段 B：结果页与 PDF 小验证

优先完成结果页桌面／手机 UI，使用显式开发样例验证 72／0／100 和未完成状态；同时用最小摘要验证中英文 PDF 和字体，尽早暴露导出风险。不要等全部 UI 完成才第一次尝试中文 PDF。

### 阶段 C：单题闭环

接通开始 → 单题答题 → 暂时跳过／回补 → 结果 → 修改 → 重新导出。加入刷新恢复、损坏数据降级和清除。

### 阶段 D：首页、收尾与验收

完善首页、FAQ、关于、隐私、语言覆盖、响应式和可访问性；执行验收清单。正式题库缺失时只交付明确演示版，不能报告正式上线就绪。

### Codex 最终必须交付

可运行的源码和锁文件；README 中的实际启动／构建／测试／部署步骤；实际题库状态与来源记录；桌面和手机关键页截图；中文／英文／双语 PDF 验证结果；测试执行记录；剩余阻塞项。

完成报告必须区分“已实现并验证”“已实现但未验证”“未实现／被阻塞”。不把 npm 安装成功、构建成功或一张截图等同于所有功能通过。没有运行过的命令和测试不得写“通过”。

若交付时正式题库仍未提供，明确写：**界面与流程可验收；正式 100 题内容未完成，不能作为正式版本发布。**
